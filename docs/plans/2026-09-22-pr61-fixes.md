> 本文档记录对 PR #61（`feat: implement #58 forced tutorial and #59 shop`）的修复范围、产品决策与验收矩阵。
> 评审结论：原实现**不可合并**（服务端锁可被一次 API 调用绕过、商店未接通、自带测试跑不起来）。

## 2. 修复架构

1. **状态机**：抽出无 prisma 依赖的纯逻辑模块 `modules/tutorial/routing.ts`（`ROUTE_MAP`/恒放行白名单/段边界匹配/`unlockedForStep`/`resolveProgress`）；`advanceTutorial` 区分 `manual|auto` 并禁止回退/跳步；只有 `completeTutorial` 能置 `tutorialCompleted`；条件式招募步由服务端核对在册人数后推进。
2. **配置管线**：`tutorial`/`shop` 由"可选 + 硬编码兜底"改为**必需文件**，删除兜底与 zod 绕过，补 `reward.item` 与 `unlock` 键的语义校验（键词表放在 `packages/shared`，避免 config 层反向依赖 module 层），fixture 补齐自洽。
3. **前端可用性**：遮罩按步骤分档（`visit_*`/纯展示步拦点击留洞；`do_*` 步只做暗场+高亮，否则窄 target 会让"先选学员再点按钮"的流程死锁）；引导状态 2s 轮询 + visit 步主动失效；守卫 fail-closed + 锁定提示。

## 5. 已知取舍与后续

- `visit_*` 步的遮罩仍拦点击（那一步用户只该点被高亮的目标），锁定项 tooltip 在该类步骤上无法悬停；`do_*` 步与引导结束后正常。
- 极端账号（4 名学员全部 V<7，达不到讲课强接下限 `门槛−8`）仍可能卡在 lecture 步 → 按"不提供用户可见跳过"的决策，只保留 `docs/OPERATIONS.md` §11 的运维放行 SQL。
- **剧情步只在通关时推进**（`story/service.ts:824`，`rank ≤ 8`）；未通关时是页内替换回放，重试需要先退出回放。失败后受体力限制（训练 1 + 讲课 2 + 历练 1×3）通常只剩 1 点体力，只能重打 1–2 次 → 极端情况下玩家要等体力恢复（45 分钟/点，上限 5），属"等待"而非永久卡死。e2e 已按此写 4 次重试，7 次连跑全部首次通关。
- 前端撞名已修：`StoryPage.tsx:432` 的页内 div 原与侧栏 `App.tsx:143` 生成的 `data-tutorial="nav-story"` 撞名。实测 `querySelector` 取文档首个匹配、侧栏在 `main` 之前渲染，所以聚光一直落在侧栏（行为正确）；但这是"靠 DOM 顺序兜着"的隐式契约（侧栏一旦挪到 `main` 之后，洞口会静默变成整个章节区），已把页内那个改名为 `story-page-intro` 消除该隐患。
- `resetUsers` 未清理 `pvpTournament`（全局表、无 user 外键），自增 id 会跨用例累积，是 `pvp-scheduler` 种子抖动的放大因素；已把该用例改为按引擎文档断言，但未根治（未改全局表清理，属既有范围外）。
- `sim:economy`/`balance-regression` 模型不含商店与引导奖励；若要把商店纳入收支红线，需要另行扩展仿真（不在本 PR）。
