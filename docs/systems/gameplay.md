## 1. 行动时钟（懒结算）

所有时间恢复资源**不做后台定时任务**，采用读时懒结算：

- 每名学员持久保存 `last_tick_at`；任何读取或行动结算时，先按
  `补足量 = floor((now − last_tick_at) / 单点恢复时长 × stamina_regen)` 补足并截断至上限，再执行本次操作。
- **体力**：上限 5；恢复速率 = `(2/3) × (stamina_regen / 50)` 点/小时——新人 regen≈48–54 即约 46–52 分钟/点（student.md §7.1）。满体力约 4 小时，玩家每日上线 1–2 轮即可清完。
- **精力**：上限 `energy_max`；恢复速率 = `10 × (1 + energy_regen/100)` 点/小时（student.md §7.2），新人约 6–8 小时回满。
- **专注（focus）**：仅赛场内临时存在，不入时钟，每场比赛开始时清零。
- 离线时间照常累计（同一公式），不存在「错过在线奖励」概念。
- 并发与原子性由服务端条件 UPDATE 保证（细节归 TECH-DESIGN.md §时钟）。

## 2. 训练系统

三种训练均消耗学员 **体力 −1** 与钱，费用随**当前学员总数 N** 线性增长：
`cost = round(base × (1 + 0.08 × (N − 1)))`（base 与线性系数以 `economy.yaml` 为权威）。

### 2.1 基础训练

| 项 | 值 |
|---|---|
| 费用 base | **60 钱**（N=5 时 79，N=10 时 103） |
| 收益对象 | 抽签决定：随机六维之一 **70%** / code **20%** / thinking **10%** |
| 增益公式 | `Δ = 1.6 × (1 − cur/100)^2` 浮点累积（cap=100，机制权威见 `student.md` §4.1） |

示例：cur=10 → Δ≈1.30；cur=50 → Δ≈0.40；cur=80 → Δ≈0.06（浮点累积、界面 floor 显示、无保底——见 student.md §4.1）。

### 2.2 定向训练

| 项 | 值 |
|---|---|
| 费用 base | **150 钱**（N=5 时 198） |
| 书籍消耗 | 每次**消耗 1 本目标维度对应六维书**（书籍稀有度提供倍率） |
| 增益公式 | `Δ = 2.0 × BookMult × (1 − cur/100)^2` 浮点累积 |

书籍倍率 `BookMult`（六维书稀有度，student.md §4.4）：灰 1.00 / 黄 1.25 / 绿 1.50 / 蓝 1.75 / 紫 2.00。定向训练仅消耗六维书；thinking/code 无训练行动、靠直用书（§2.4）；setting 靠直用书与出题实践成长。

### 2.3 专项训练（题库联动）

| 项 | 值 |
|---|---|
| 费用 base | **100 钱**（预制题另有获取成本，钱费介于基础与定向之间） |
| 题目消耗 | **消耗 1 道自制预制题**（入库题被用于训练后销题），取其主导维度为目标 |
| 增益公式 | `Δ = 3.2 × QualityMult × (1 − cur_target/100)^2`；`QualityMult` 按题稀有度：灰 1.00 / 黄 1.10 / 绿 1.20 / 蓝 1.30 / 紫 1.45 / 彩 1.60（student.md §4.2） |

以灰书定向为基准（2.0）：专项 3.2 起步、高质量题可达 ×1.6——期望效率约为定向的 1.2–2.5 倍，且题近乎零边际成本；受题库供给约束，形成「出题→喂训练」闭环。

### 2.4 书籍消耗规则汇总

- 定向训练：每场次消耗 1 本对应书；书在**结算时扣除**，库存不足则无法发起。
- **书籍二分**（student.md §4.4 权威）：六维书**只能**作定向训练耗材、不可直接使用；thinking/coding/setting 直用书才是背包即用道具（固定增益 灰+2 / 黄+4 / 绿+7 / 蓝+12 / 紫+20，不走递减、同学员同属性每周 ≤10 点）。
- 训练不消耗改名卡、进阶石等养成道具。

### 2.5 每日次数限制

训练**无独立每日次数上限**：体力上限 5 已构成天然硬约束（训练还要与历练、出题竞争体力）。刻意不加钱费以外的软限制，保持规则面简单；若 M5 数值平衡发现刷钱漏洞，再经 economy.yaml 加衰减参数。

### 2.6 极低概率稀有成长

每次训练结算后独立掷以下四项（互不排斥，可同次叠加）：

| 属性 | 概率 | 幅度 | 上限 |
|---|---|---|---|
| mindset | **3%** | +1（不超过 +10） | +10 |
| setting | **2%** | +1 | 100 |
| focus_cap | **0.8%** | +1 | 100 |
| stamina_regen | **0.5%** | +1 | 100 |

单次训练约 **6.2%** 概率获得至少一项稀有成长；以日均 10 次训练计，学员约每 1–2 天出现一次稀有成长，长期挂机有缓慢的横向养成曲线（概率与幅度权威：student.md §4.5）。

## 3. 历练系统

### 3.1 行动流程

1. 玩家选择一名体力足够的学员，投入 **1 / 2 / 3 体力**之一。
2. 系统只在**体力消耗恰等于投入档**的事件层内抽取（精确分层，非 ≤ 过滤）：投 1 抽便宜高频事件，投 3 直入高风险高回报池。
3. 先按事件 `requirements` 过滤（声誉门槛、属性门槛不满足的事件不进池），再剔除冷却中、一次性已触发、周限量已用尽的事件。
4. 按 §3.2 权重抽出一条事件，进入其 choices → outcomes 结算。

### 3.2 稀有度权重表（各层和为 100）

| 投入档 | 层内存在的稀有度 | 权重 |
|---|---|---|
| −1 | gray / yellow | `{gray: 70, yellow: 30}` |
| −2 | yellow / green / blue / purple | `{yellow: 42, green: 34, blue: 20, purple: 4}` |
| −3 | green / blue / purple / colorful | `{green: 25, blue: 35, purple: 31, colorful: 9}` |

单事件最终概率 = `layer_weight[投入档][rarity] × event.weight ÷ Σ(同 rarity 同层事件 weight)`。events.yaml 中每条的 `weight` 是**组内权重**（同稀有度同体力层的相对占比），各组内部和为 100。

### 3.3 冷却机制

- 采用**单事件冷却**（而非同类冷却）：账号级记录每事件上次触发时刻，冷却未过的条目从池中剔除。理由：同类冷却会让偏爱某类玩法（如专打对决）的玩家被系统性惩罚；单事件冷却只防「连刷同一个高价值事件」。
- 冷却天数按现实时间懒结算（复用 §1 时钟）：灰黄 0–2 天，绿蓝 0–5 天（R6 长冷却 5 天），紫 3–4 天，彩 7 天，逐条见 events.yaml 的 `cooldown_days`。
- 麻烦类负面事件同样带冷却（1–3 天），保证倒霉事有节奏而不连续轰炸。

### 3.4 一次性与限量事件

| 字段 | 语义 |
|---|---|
| `repeatable: false` + `once_per_student: true` | R7 强者指点：**每名学员限触发一次**；已触发过的学员不再抽到（其余学员仍可能抽到，全员触完后自然绝迹） |
| `repeatable: false` + `server_weekly_limit: 3` | C2 图灵之遗：**全服每周限量 3 次**（周一 00:00 重置）；本周额度耗尽后从全服所有玩家的池中移除 |

### 3.5 情报预览机制（intel-slip）

- 使用道具 `intel-slip` 后账号获得「情报」状态（无时限，直到被消费）。
- 处于情报状态时发起历练：服务端**先完成抽取**并向玩家展示结果事件的名牌（名称/类别/稀有度/体力档），此时玩家二选一：
  - **执行**：正常扣体力、正常结算；
  - **回避**：本次历练取消，**不扣体力**，事件回到池中，情报状态消耗。
- 预览只显示事件身份，**不显示选项内容与结果分支**——情报的价值是规避麻烦类事件、锁定彩事件，而非白拿全部信息。

### 3.6 非对决事件的通用判定公式

试炼/考验类 outcome 使用统一检定：

```
p_success = sigmoid((S − DC) / 12)，S = 相关属性 + 天赋修正（talents.yaml）
margin    = S − DC（用于分级奖励 grades：margin ≥ 阈值给高档）
```

多题小型赛（Y1 校内模拟赛）逐题独立检定，按解出题数分档发奖。对决类 outcome 只引用 `duel` 参数块，内部算法归 contest.md。

## 4. 高级学院

### 4.1 招募

| 项 | 值 |
|---|---|
| 学员池容量 | **5 名**候选同时展示 |
| 免费刷新 | 每 **24 小时**自动刷新一次（懒结算：距上次刷新 ≥24h 时读时触发） |
| 手动付费刷新 | 当日第 n 次价格 `round_to_10(100 × 1.5^(n−1))`，即 100 / 150 / 230 / 340 / 510 / 760 / 1140 / 1710 / 之后封顶 **2000**；每日零点重置次数 |
| 品质档权重 | 普通 **62%** / 良好 **27%** / 精英 **9%** / 天才 **2%** |
| 声誉对品质的影响 | 精英+天才合计权重 ×`(1 + min(reputation, 1000)/1000)`（最高 ×2）后重新归一化——声誉 500 以上高阶候选约翻倍，属「弱影响」 |
| 招募费用 | `round(300 × 1.35^N)`（N=当前学员数），再乘品质系数：普通 ×1.0 / 良好 ×1.5 / 精英 ×2.5 / 天才 ×5.0 |

招募费示例：0 名学员招普通人 300；5 名学员招精英 `1331×2.5 ≈ 3328`；8 名学员招天才 `3309×5 ≈ 16547`。指数曲线让后期扩张显著变贵。品质档对玩家隐性，仅以模糊评语提示；属性期望与天赋数由 student.md 定义（**依赖注明**）。声誉对候选属性的加成公式同样引用 `systems/student.md` 口径，本文不重复定义。

### 4.2 讲课

**教学力**：`V = round((code + thinking + avg(six dims)) / 3)`。

受众五档门槛与基础报酬（数值权威 `economy.yaml`；声誉乘区见下）：

| 档位 | 门槛 V | 基础报酬（钱） | 基础声誉 |
|---|---|---|---|
| 入门组 | 15 | 60 | 1 |
| 普及组 | 30 | 150 | 2 |
| 提高组 | 45 | 300 | 4 |
| 省选组 | 62 | 800 | 8 |
| 国家队集训队 | 80 | 2000 | 15 |

- **能力溢出加成**（声誉侧）：`声誉产出 = base_rep × (1 + 0.04 × min(V − threshold, 25))`，最高 +100%（每溢出 5 点 +20%）。
- **声誉对钱的乘区**：`实收 = base_pay × clamp(1 + reputation/500, 1, 3)`。声誉 0 → 基准，500 → ×2，1000 及以上 → ×3 封顶。此乘区只作用于钱，不作用于声誉产出，避免声誉正反馈滚雪球。
- **能力不足强接**：允许区间 `threshold−8 ≤ V < threshold`，接单即进入风险结算：
  - **40% 讲砸**：收入 0，声誉 `−2×(档位序号)`（即 −2/−4/−6/−8/−10），主讲学员 mindset −2；
  - **60% 勉强过关**：收入 ×0.6，声誉 `−1×(档位序号)`；
  - V < threshold−8 时不可接单（硬下限，防止无意义送声誉）。
- **每日次数**：全营合计 **3 场/日**；同一名学员每日最多出场 **2 场**。历练事件 R8 的代课不计入每日额度。

收入锚点：中期玩家（rep≈100 → 乘区×1.2，V≈45 可接提高组 300）三场 ≈ **1080 钱/日**，配合比赛奖金与历练收入达成「周收支≈持平略正」（economy.yaml 模拟：典型周净 +116）。

## 5. 出题玩法（题库闭环）

### 5.1 行动成本

| 项 | 值 |
|---|---|
| 体力 | 参与学员 **−1** |
| 钱 | `round(20 × (1 + 0.15×(N−1)))`（打磨/评测机时） |
| 次数限制 | 每名学员 **≤2 次/日**（防止单一高 setting 学员无限灌库） |
| 结算方式 | 即时完成（懒结算架构下无需等待队列） |

玩家指定**主考六维**（target dim）后开始出题。

### 5.2 质量评级规则

```
Q = clamp( round(0.55×setting + 0.25×target_dim + 0.20×thinking + U(−8,+8)), 0, 100 )
```

- 出题能力为主导（55% 权重）；对目标维度的掌握深浅决定题目扎实程度（25%）；思维能力决定题目的巧思（20%）；±8 随机浮动制造波动。
- 特性附带概率：`p = min(0.05 + setting × 0.002, 0.35)`（setting 50 → 16%，100 → 25% 封顶）；特性严重度阶梯（红<黄<蓝<紫<黑<彩，GAME-DESIGN §5 独立序列）按 setting 加权上移，映射细则归 problems.yaml。

评级分层（映射回统一六色序列展示）：

| Q 区间 | 评级 | 色 |
|---|---|---|
| <30 | 习作 | gray |
| 30–49 | 合格 | yellow |
| 50–69 | 良好 | green |
| 70–84 | 优秀 | blue |
| 85–94 | 杰作 | purple |
| ≥95 | 传世 | colorful |

### 5.3 入库规则

- 题目进入**账号级题库**，容量上限 **120 道**；满库时必须选择销毁若干旧题方可入库（UI 按评级排序提示销毁最低档）。
- 题库内按评级分层展示，支持按主考维度筛选。
- 预制题的三种去向：① 对决携带（替换临场生成题）；② 专项训练消耗；③ PVP 己方赛场题。用于②时销题，用于①③时不消耗、可重复携带。

### 5.4 引用边界

| 用途 | 规则归属 |
|---|---|
| 对决中可携带数量、替换哪一局、质量加成结算 | `systems/contest.md` |
| PVP 己方赛场题与「对手答错→己方声誉收益」 | `systems/contest.md` |
| 专项训练的消耗与增益公式 | 本文 §2.3 |
| 出题行动本身、质量公式、入库 | 本文 §5 |
| R4 事件胜出后的成品入库（quality_mult ×1.1） | events.yaml `bank_add` 字段 |
